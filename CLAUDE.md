# Fantasy Golf League site

Static one-page site (GitHub Pages) + Supabase (Postgres) backend for GP's fantasy golf league.

## Files
- `index.html` — the entire site: HTML, CSS and vanilla JS in one file. Loads `@supabase/supabase-js@2` UMD from jsDelivr and `config.js`.
- `config.js` — `window.LEAGUE_CONFIG = { SUPABASE_URL, SUPABASE_ANON_KEY, LEAGUE_NAME }`. Anon key is public by design.
- `supabase/schema.sql` — idempotent; run in the Supabase SQL editor. Tables, RLS, all RPC functions, 2027 schedule seed (30 events incl. Pebble Beach, 2026 purses as placeholders), golfer autocomplete seed, commissioner PIN seed (`1234` placeholder — GP must change).
- `README.md` — setup walkthrough for GP (non-developer).

## League rules the code enforces (server-side, in schema.sql)
- One golfer per owner per tournament. Owners may change their pick until `tournaments.lock_at`.
- **No mulligans**: a golfer can be used once per season per owner. Matching is on `golfer_key` (lower-cased, whitespace-collapsed).
- Before lock: everyone can see *who* has picked, never *which* golfer. After lock: picks revealed and frozen. `tournament_board()` does the masking.
- Scoring: `picks.winnings` (golfer's actual prize money, entered by commissioner) × `tournaments.multiplier`. Season total = standings.
- Default lock: Thursday 07:00 America/New_York. Event selection/multipliers follow GP's "Fantasy Golf 2026" Google Sheet, applied to the 2027 PGA Tour schedule (announced Aug 26 2026). The 2026 season was over before launch, so the site ships on season 2027.
- Zurich Classic (two-man team event) is deliberately a normal single pick at 2× — GP's call, Sep 2026.
- Autocomplete (`list_golfers()`) = seed table ∪ golfers from locked tournaments. `submit_pick` must NOT write to `golfers` — that leaked pre-lock picks.
- **Cards** (Sep 2026): the commissioner deals TCG-style cards (`cards` table) to owners; only the owner sees their hand (`my_cards`), plays one per tournament before lock (`play_card`/`unplay_card`), and plays reveal at lock (`tournament_cards`). **All points flow through `scored_points(tournament_id)`** — winnings × multiplier, then cards applied in `played_at` order: `multiply {x}`, `flat {amount}`, `duel` (higher raw winnings → ×2 base, loser 0; tie no-op), `steal {pct}`, `swap`, `shield` (nullifies duel/steal/swap/curse aimed at the holder), `mulligan` (lets `submit_pick` reuse a golfer that week), `custom` (text only — the commissioner rules on it via the per-pick **adjustment**: `picks.adjust` + `adjust_note`, set from Enter Results through `admin_set_winnings(..., p_adjust, p_adjust_note)`, applied by `scored_points` after every card and noted as "Commissioner: +$X (why)"), `fellowship {amount}` (partner card — both owners must play it on each other; +amount each, both $0 if either has $0 winnings = missed cut; resolved once per pair via `paired[]`), `curse {golfer, pct}` (In the Stocks: victim's points × (1+pct/100); if `golfer` set, `submit_pick` rejects any other pick for the victim — and skips the no-mulligan rule for the forced golfer — and scoring zeroes them if they didn't comply; the victim alone is warned via `my_constraints()` on the pick form, without learning who played it). `tournament_board`/`standings`/`season_picks`/`my_picks` all read from it and carry a `note` explaining the math. Adding an effect = add it to the `check` constraint, the `case` in `scored_points`, and `EFFECTS` in index.html (label/param/target/summary). Card art is stored as a data URL made in the browser — no storage bucket. **Art editor (Sep 22 2026):** in the designer preview the art window is draggable (pan) and zoomable (wheel or the `#dcZoom` slider, 1–4×, `Reset art`); state `dcArt={x,y,s}` (focal point fractions + zoom, s from 0.3 to 4 — below 1 the picture floats on the window's dark backing). Placement math lives in ONE function, `artPlace(a, iw, ih)` (cover-fit, scale about the focal point, edge at x·(window−media), as % of the window) and is used for the preview, for live video placement (`data-art` attribute + `placeArt()` on load/loadedmetadata) and for `bakeArt()` (640×502 JPEG, backing gradient painted first) — so what you see is what is stored. Do NOT go back to `object-fit:cover` + `transform:scale`: object-fit clips the overflow before the transform, so zooming out showed a cropped picture while the bake showed the whole one (Sep 22). Stills: the upload is kept ≤1600px as the crop source (`dcArtImg`); `dcImageOut()` returns null when nothing changed so the library art is kept. Editing a library card reloads its stored art as the crop source, so old cards can be re-cropped. Videos are stored as-is and their `_art` rides in `params._art`, applied live by `artEl()`. `artEl` now wraps media in the `.mc-art` div (`overflow:hidden`) so a zoomed image can't spill under the frame. Full-card images have no art editor. **Animated art (Sep 17 2026):** the same input accepts MP4/WebM; the file is stored as-is as a `data:video/...` URL (cap 8 MB in the UI, advise 2–3 MB), `artEl()`/`isVideo()` render it as a muted looping `<video>` in the art window or as the whole card (`full_card`), and the announce edge function attaches a video as `cardN.mp4` (Discord embeds can't hold video, so the embed carries the text and the attachment plays under the message).
- **Painted tier frames (Sep 17 2026, the current card look):** `frames/{common,rare,legendary,mythic}.png` (768×1152, 32-bit alpha) are George's ChatGPT-generated EMPTY templates — transparent art window, blank bars/panels, emblems kept — simply downscaled from `fantasy-golf-site\Card Templates\*.png` (1024×1536, outside the repo). ## Security model — keep it this way
- The browser holds only the anon key. **All tables have RLS on and zero grants to anon/authenticated.** Nothing is readable or writable directly.
- Every read/write goes through `security definer` functions; only those are granted to `anon`. Owner functions take `(p_owner, p_pin)` and call `_owner_id()`; commissioner functions take `p_admin_pin` and call `_check_admin()`. PINs are hashed with pgcrypto `crypt()`.
- When adding a function: `security definer set search_path = public, extensions` (Supabase installs pgcrypto in `extensions`; plain `public` breaks `crypt()` — bit us on launch day), add it to the `grant execute ... to anon, authenticated` list at the end of the schema, and never expose an unlocked golfer name from it.
- Frontend calls functions with `sb.rpc(name, {p_...})` via the `rpc()` helper in index.html; errors thrown there surface as user-facing messages.

## Discord
`settings.discord_webhook` (set via `admin_set_discord`, never exposed). `announce_locked()` runs from pg_cron job `announce-locks` every 5 min: any tournament with `lock_at <= now()` in the last 2 days and `announced_at is null` → `_discord_post(id)`, then stamps `announced_at`. `_discord_post` calls the **`announce` edge function** (`supabase/functions/announce/index.ts`, deployed via Management API `POST /v1/projects/{ref}/functions/deploy?slug=announce`, `verify_jwt:false`; auth = `x-announce-key` header matching the `ANNOUNCE_KEY` function secret and `settings.announce_key`; URL in `settings.announce_url`). The function reads with the service role (needs `grant all on all tables ... to service_role` — tables made through the SQL API don't get it), calls `_discord_message` + `_discord_cards`, and posts multipart to the webhook: picks as text, each card in play as an embed with its art attached (`attachment://cardN.jpg`), text-only embeds for cards without art. If `announce_key`/`announce_url` are missing it falls back to a text-only `net.http_post` to the webhook. The announcer key is at `~/.secrets/golf_announce_key` on GP's PC. `_discord_message` = picks + cards in play when locked; "who's in so far" when not. `admin_announce` posts on demand (Enter Results → "Announce on Discord") and returns the text. The DO blocks that create pg_net/pg_cron and (re)schedule the job swallow errors so the schema still loads on a project without them; `admin_discord_status.scheduled` tells the UI.

## Live scoring + stroke adjustments (Sep 17 2026)
Effect `strokes` (params `{n}`, signed, target = the affected owner): +N adds strokes to the target golfer (hurts), −N removes them (helps). George renamed it "Stroke adjustment" for versatility; UI labels use `fmtStrokes` / SQL `_strokes_txt` (amber badge when +, green when −). It is applied **automatically** via live scores, not by the commissioner. Pipeline: pg_cron job `sync-scores` (every 10 min) → `sync_scores()` → `net.http_post` to the **`scores` edge function** (`supabase/functions/scores/index.ts`, URL in `settings.scores_url`, same `x-announce-key` auth) → fetches ESPN's public PGA leaderboard `https://site.web.api.espn.com/apis/site/v2/sports/golf/leaderboard?league=pga` (send `User-Agent: curl/8.4.0`; ESPN 403s browser-ish/PowerShell agents), matches each event to a tournament by `start_date` within ±3 days, and upserts the whole field into `live_scores.field` (jsonb: name, key=normalised name, pos, posn, score=to-par from `statistics[scoreToPar]` — `score.displayValue` lags mid-round —, strokes, thru, state, earnings). `sync_scores()` only fires while a tournament locked in the last 4 days exists. Public RPC `live_board(tournament_id)` (post-lock only) matches each owner's pick to the field (`_norm` exact, then surname + first initial), adds `tournament_penalties` strokes to the to-par score, re-ranks that adjusted score against the live field (`adj_pos`/`adj_ties`), and projects money: real ESPN earnings at the adjusted finish when `STATUS_FINAL`, else `tournaments.prize_pool × _payout_pct` (standard Tour distribution, ties averaged). UI: This Week shows a **Live leaderboard** card (auto-refreshes every 2 min while open) with a signed "+N / −N strokes" badge (adjusted to-par = score + N). At `STATUS_FINAL` the function calls `_autofill_winnings` → `picks.winnings` + `winnings_source='auto'`; `admin_set_winnings` marks `manual` and autofill never overwrites manual rows. Commissioner → Enter Results has **Fill from live scores** (`admin_autofill_winnings`). Discord lock post lists stroke adjustments next to the pick (⚠️ for +, ✨ for −). Verified Sep 17 2026 against the live Biltmore Championship (ESPN event 401850914): −4/T1 + 3 strokes → −1/T12, projection dropped from $1.30M to $120K.

## Card timing rules (Sep 17 2026) — the ledger is `RULES.md`

## Tees + booster packs (Sep 22 2026, RULES.md 14–17)
`card_library.cost` / `cards.cost` (0–3, designer "Tee cost" select, tee pips drawn on the type-bar blade by `costPips`, `costTag` in the foot). `play_card` refuses a card when spent tees + cost > 3 for that tournament (in addition to the 3-card cap). My Cards shows "N of 3 tees left" under each Play form for the selected week (`updTees`). **Packs:** `packs` table (one row per owner per tournament), `cards.pack_id`. `_award_packs(tournament_id)` gives every active owner 5 cards: `_pack_tier(slot)` rolls the tier (1–3: 80/20 common/rare; 4: 50/40/10; 5: 70/25/5 rare/legendary/mythic), `_pick_library_card(tier)` picks a random non-retired design of that tier, stepping down a tier if empty. Triggered three ways: the `scores` edge function at STATUS_FINAL, pg_cron `award-packs` (hourly, `award_due_packs()` for ended tournaments in the last 14 days with no packs), and Commissioner → Enter Results → "Open booster packs" (`admin_award_packs`). Idempotent per (tournament, owner). Discord gets `_packs_message` (rarity counts only). `packs.revealed_at` is null until the owner opens the pack on the site (`open_pack(owner, pin, pack_id)`); My Cards hides cards of sealed packs and shows a glowing **sealed pack** button per pack (`#packNote`), plus a "Pack history" list with Replay. `openPackUI(pack, replay)` (exposed on `window.__mgl`) runs the Hearthstone-style opening in `#packOverlay`: tap the pack → shake/burst → five face-down cards deal into an arc → tap to flip (3D `rotateY`, tier glow, full-screen flash for legendary/mythic) → "Add to hand" calls `open_pack` and reloads. Gotchas: the overlay is re-parented to `<body>` at startup (header/main/footer each start a stacking context, so a fixed overlay inside `<main>` painted under the footer), and it must NOT have `backdrop-filter` — Chromium then drops the 3D-flipped cards from the composite (only one card rendered). Tee cost is a numeral in the title bar's top-right circle (`.mc-cost`, over the painted crown, dark disc behind it) — George moved it there from the type-bar blade.
