# Fantasy Golf League site

Static one-page site (GitHub Pages) + Supabase (Postgres) backend for GP's fantasy golf league.

## Files
- `index.html` — the entire site: HTML, CSS and vanilla JS in one file. Loads `@supabase/supabase-js@2` UMD from jsDelivr and `config.js`.
- `config.js` — `window.LEAGUE_CONFIG = { SUPABASE_URL, SUPABASE_ANON_KEY, LEAGUE_NAME }`. Anon key is public by design.
- `supabase/schema.sql` — idempotent; run in the Supabase SQL editor. Tables, RLS, all RPC functions, 2027 schedule seed (30 events incl. Pebble Beach, 2026 purses as placeholders), golfer autocomplete seed, commissioner PIN seed (`1234` placeholder — GP must change).
- `README.md` — setup walkthrough for GP (non-developer).

## League rules the code enforces (server-side, in schema.sql)
- One golfer per owner per tournament. Owners may change their pick until `tournaments.lock_at`.
- **No mulligans**: a golfer can be used once per season per owner. Matching is on `golfer_key` (lower-cased, whitespace-collapsed).
- Before lock: everyone can see *who* has picked, never *which* golfer. After lock: picks revealed and frozen. `tournament_board()` does the masking.
- Scoring: `picks.winnings` (golfer's actual prize money, entered by commissioner) × `tournaments.multiplier`. Season total = standings.
- Default lock: Thursday 07:00 America/New_York. Event selection/multipliers follow GP's "Fantasy Golf 2026" Google Sheet, applied to the 2027 PGA Tour schedule (announced Aug 26 2026). The 2026 season was over before launch, so the site ships on season 2027.
- Zurich Classic (two-man team event) is deliberately a normal single pick at 2× — GP's call, Sep 2026.
- Autocomplete (`list_golfers()`) = seed table ∪ golfers from locked tournaments. `submit_pick` must NOT write to `golfers` — that leaked pre-lock picks.
- **Cards** (Sep 2026): the commissioner deals TCG-style cards (`cards` table) to owners; only the owner sees their hand (`my_cards`), plays one per tournament before lock (`play_card`/`unplay_card`), and plays reveal at lock (`tournament_cards`). **All points flow through `scored_points(tournament_id)`** — winnings × multiplier, then cards applied in `played_at` order: `multiply {x}`, `flat {amount}`, `duel` (higher raw winnings → ×2 base, loser 0; tie no-op), `steal {pct}`, `swap`, `shield` (nullifies duel/steal/swap/curse aimed at the holder), `mulligan` (lets `submit_pick` reuse a golfer that week), `custom` (text only — the commissioner rules on it via the per-pick **adjustment**: `picks.adjust` + `adjust_note`, set from Enter Results through `admin_set_winnings(..., p_adjust, p_adjust_note)`, applied by `scored_points` after every card and noted as "Commissioner: +$X (why)"), `fellowship {amount}` (partner card — both owners must play it on each other; +amount each, both $0 if either has $0 winnings = missed cut; resolved once per pair via `paired[]`), `curse {golfer, pct}` (In the Stocks: victim's points × (1+pct/100); if `golfer` set, `submit_pick` rejects any other pick for the victim — and skips the no-mulligan rule for the forced golfer — and scoring zeroes them if they didn't comply; the victim alone is warned via `my_constraints()` on the pick form, without learning who played it). `tournament_board`/`standings`/`season_picks`/`my_picks` all read from it and carry a `note` explaining the math. Adding an effect = add it to the `check` constraint, the `case` in `scored_points`, and `EFFECTS` in index.html (label/param/target/summary). Card art is stored as a data URL resized in the browser (`dcImage` handler; 640px for artwork, 760px for full cards) — no storage bucket.
- **Painted tier frames (Sep 17 2026, the current card look):** `frames/{common,rare,legendary,mythic}.png` (768×1152, 32-bit alpha) are George's ChatGPT-generated EMPTY templates — transparent art window, blank bars/panels, emblems kept — simply downscaled from `fantasy-golf-site\Card Templates\*.png` (1024×1536, outside the repo). No erasing/inpainting is needed any more (the first-generation frames had baked text; that pipeline is obsolete). Measured on the 1024×1536 originals: art window x 80–956 / y 186–872 (alpha edge is crisp), title bar interior x 100–790 / y 75–175, type bar x 130–790 / y 838–905, text panel x 105–935 / y 950–1360, collector bar y 1415–1455 (texts at x 110–420 and 620–920). The `.mc` renderer in `tcgHTML` layers `.mc-art` (7.8%/12.1%/85.5%/44.7% — overshoots into the opaque frame on purpose), `.mc-frame`, `.mc-title` + `.mc-type` (Sep 17 2026: same beveled, extruded Cinzel capitals as the site title — gradient face on an inner `<span>` above `::before` rim and `::after` extrusion that repeat `data-text`; **silver on common/rare, gold on legendary/mythic**. The face must be on the span, not the div: an element's own background paints below its negative-z pseudo-elements. `window.__mgl = {tcgHTML, fitCards}` is exposed for console previews; a local preview server is `python -m http.server 8765` in the repo folder), `.mc-text` (EB Garamond; ✦ divider before flavor), `.mc-coll` collector line (`MGL · <library id> · TIER` / `The Mattlemore Golf League`). Legendary/Mythic get `.holo` sheen + cursor tilt (`data-tilt`). The older CSS-only `.tcg` frame is unused except `.tcg.full` for finished full-card images. If George regenerates a template, re-measure with the alpha-bbox + zoom-grid approach before trusting old numbers. `full_card` (on `cards` and `card_library`): the league's real cards are finished images (title/type/text baked in, portrait ~2:3) — render them as-is (`.tcg.full`), auto-detected on upload when height/width > 1.25. The built-in frame for text-only cards deliberately mimics those printed cards: near-black body, double gold border with corner scroll SVGs (`--curl`), parchment panels with feTurbulence grain (`--noise`), EB Garamond; all frame sizes are in `cqw` (`container-type:inline-size`) with grid rows 7/46/6/31 measured off the paintings, so cards scale like prints and `fitCards()` only shrinks text that overflows. `EFFECTS[x].params` is an array of `{k,l,t}` inputs rendered by `dcRenderParams`; `EFFECTS[x].target` is the label for the owner it's played on (Opponent/Victim/Partner) or absent.
- **Tiers** (Sep 16 2026): `tier` on `card_library` and `cards` — common < rare < legendary < mythic (George's ladder, revised Sep 17 2026: grey / blue / **purple** / **orange**; holo on legendary + mythic). Data + designer selector + badge in the card strip + Discord embed colour are live; the per-tier *frame* visuals are pending George's sign-off on the MTG-style mockup (`scratchpad/card-frame-v3.html`). `TIERS` in index.html mirrors the check constraint.
- **Library filters**: search (name/kind/rules/flavor), tier, effect, status (active / never dealt / dealt / in hands / retired / all) — pure client-side over `libRows` (`libFilter`/`renderLibrary`).
- **Card library** (`card_library`, George: "build up a huge pool"): the season-independent pool of designs. Dealt `cards` rows carry `library_id`; `admin_deal_from_library` copies the design into a new card. Commissioner UI: "Card library" grid (deal to owner / edit / retire-restore, with dealt counts) above the "Design a card" form; dealing a new design ALWAYS saves it to the library first (George: "all cards should appear in the card library"; the old opt-out checkbox is gone), `dcLibId` marks edit mode. `admin_deal_card` (library-less deal) is kept in SQL but the UI no longer calls it. Retire hides from the pool but never deletes. `admin_save_library_card` with null image keeps existing art.

## Security model — keep it this way
- The browser holds only the anon key. **All tables have RLS on and zero grants to anon/authenticated.** Nothing is readable or writable directly.
- Every read/write goes through `security definer` functions; only those are granted to `anon`. Owner functions take `(p_owner, p_pin)` and call `_owner_id()`; commissioner functions take `p_admin_pin` and call `_check_admin()`. PINs are hashed with pgcrypto `crypt()`.
- When adding a function: `security definer set search_path = public, extensions` (Supabase installs pgcrypto in `extensions`; plain `public` breaks `crypt()` — bit us on launch day), add it to the `grant execute ... to anon, authenticated` list at the end of the schema, and never expose an unlocked golfer name from it.
- Frontend calls functions with `sb.rpc(name, {p_...})` via the `rpc()` helper in index.html; errors thrown there surface as user-facing messages.

**Every push must bump `const BUILD`** (format `YYYY-MM-DD-N`, top of the script). GitHub Pages caches index.html for 10 min; on load the page fetches the live copy with `cache: 'no-store'` and hops to `?v=<newBUILD>` if it differs — this is what stops owners running stale code (GP hit this on Sep 16 2026 and thought the library edit was broken).

Theme (Sep 2026, GP's brief): purple + green fantasy, white stag mascot. ## Discord
`settings.discord_webhook` (set via `admin_set_discord`, never exposed). `announce_locked()` runs from pg_cron job `announce-locks` every 5 min: any tournament with `lock_at <= now()` in the last 2 days and `announced_at is null` → `_discord_post(id)`, then stamps `announced_at`. `_discord_post` calls the **`announce` edge function** (`supabase/functions/announce/index.ts`, deployed via Management API `POST /v1/projects/{ref}/functions/deploy?slug=announce`, `verify_jwt:false`; auth = `x-announce-key` header matching the `ANNOUNCE_KEY` function secret and `settings.announce_key`; URL in `settings.announce_url`). The function reads with the service role (needs `grant all on all tables ... to service_role` — tables made through the SQL API don't get it), calls `_discord_message` + `_discord_cards`, and posts multipart to the webhook: picks as text, each card in play as an embed with its art attached (`attachment://cardN.jpg`), text-only embeds for cards without art. If `announce_key`/`announce_url` are missing it falls back to a text-only `net.http_post` to the webhook. The announcer key is at `~/.secrets/golf_announce_key` on GP's PC. `_discord_message` = picks + cards in play when locked; "who's in so far" when not. `admin_announce` posts on demand (Enter Results → "Announce on Discord") and returns the text. The DO blocks that create pg_net/pg_cron and (re)schedule the job swallow errors so the schema still loads on a project without them; `admin_discord_status.scheduled` tells the UI.

## Live scoring + stroke adjustments (Sep 17 2026)
Effect `strokes` (params `{n}`, signed, target = the affected owner): +N adds strokes to the target golfer (hurts), −N removes them (helps). George renamed it "Stroke adjustment" for versatility; UI labels use `fmtStrokes` / SQL `_strokes_txt` (amber badge when +, green when −). It is applied **automatically** via live scores, not by the commissioner. Pipeline: pg_cron job `sync-scores` (every 10 min) → `sync_scores()` → `net.http_post` to the **`scores` edge function** (`supabase/functions/scores/index.ts`, URL in `settings.scores_url`, same `x-announce-key` auth) → fetches ESPN's public PGA leaderboard `https://site.web.api.espn.com/apis/site/v2/sports/golf/leaderboard?league=pga` (send `User-Agent: curl/8.4.0`; ESPN 403s browser-ish/PowerShell agents), matches each event to a tournament by `start_date` within ±3 days, and upserts the whole field into `live_scores.field` (jsonb: name, key=normalised name, pos, posn, score=to-par from `statistics[scoreToPar]` — `score.displayValue` lags mid-round —, strokes, thru, state, earnings). `sync_scores()` only fires while a tournament locked in the last 4 days exists. Public RPC `live_board(tournament_id)` (post-lock only) matches each owner's pick to the field (`_norm` exact, then surname + first initial), adds `tournament_penalties` strokes to the to-par score, re-ranks that adjusted score against the live field (`adj_pos`/`adj_ties`), and projects money: real ESPN earnings at the adjusted finish when `STATUS_FINAL`, else `tournaments.prize_pool × _payout_pct` (standard Tour distribution, ties averaged). UI: This Week shows a **Live leaderboard** card (auto-refreshes every 2 min while open) with a signed "+N / −N strokes" badge (adjusted to-par = score + N). At `STATUS_FINAL` the function calls `_autofill_winnings` → `picks.winnings` + `winnings_source='auto'`; `admin_set_winnings` marks `manual` and autofill never overwrites manual rows. Commissioner → Enter Results has **Fill from live scores** (`admin_autofill_winnings`). Discord lock post lists stroke adjustments next to the pick (⚠️ for +, ✨ for −). Verified Sep 17 2026 against the live Biltmore Championship (ESPN event 401850914): −4/T1 + 3 strokes → −1/T12, projection dropped from $1.30M to $120K.

## Card timing rules (Sep 17 2026) — the ledger is `RULES.md`
George is accumulating league rulings; **every new rule goes into `RULES.md` first** (numbered, dated) and is then enforced in `play_card`. A Rules page on the site is planned once the list settles. Current: (a) non-Instant cards only before lock; (b) a card whose `kind` contains "Instant" (`_is_instant`) may be played after lock until `_instant_cutoff(start_date)` = 8 PM ET on day 3; (c) after that only an owner who has been *targeted* by an Instant in that tournament may play an Instant, until `_tournament_end` (midnight ET after day 4); on the final day (`_final_day`, day 4) that response may only target someone who already hit them with an Instant; (d) max 3 played cards per owner per tournament unless `cards.exempt_limit` (copied from `card_library.exempt_limit`, designer checkbox "exempt from the 3-cards-per-tournament limit"). The old unique index `cards_one_in_play_per_week` is dropped by the schema. Mid-tournament plays return `live:true`, are public at once via `tournament_cards`, and post a text-only Discord line through `_discord_text` (swallows errors). My Cards lists "under way" tournaments as play targets for Instants only. Tested Sep 17 2026 with temp owners/tournaments in one transaction (`scratchpad/rules_test.sql` pattern: rename `settings.discord_webhook` during the test so nothing posts, restore + delete at the end).
