# Fantasy Golf League site

Static one-page site (GitHub Pages) + Supabase (Postgres) backend for GP's fantasy golf league.

## Files
- `index.html` — the entire site: HTML, CSS and vanilla JS in one file. Loads `@supabase/supabase-js@2` UMD from jsDelivr and `config.js`.
- `config.js` — `window.LEAGUE_CONFIG = { SUPABASE_URL, SUPABASE_ANON_KEY, LEAGUE_NAME }`. Anon key is public by design.
- `supabase/schema.sql` — idempotent; run in the Supabase SQL editor. Tables, RLS, all RPC functions, 2027 schedule seed (30 events incl. Pebble Beach, 2026 purses as placeholders), golfer autocomplete seed, commissioner PIN seed (`1234` placeholder — GP must change).
- `README.md` — setup walkthrough for GP (non-developer).

## League rules the code enforces (server-side, in schema.sql)
- One golfer per owner per tournament. Owners may change their pick until `tournaments.lock_at`.
- **No mulligans**: a golfer can be used once per season per owner. Matching is on `golfer_key` (lower-cased, whitespace-collapsed).
- Before lock: everyone can see *who* has picked, never *which* golfer. After lock: picks revealed and frozen. `tournament_board()` does the masking.
- Scoring: `picks.winnings` (golfer's actual prize money, entered by commissioner) × `tournaments.multiplier`. Season total = standings.
- Default lock: Thursday 07:00 America/New_York. Event selection/multipliers follow GP's "Fantasy Golf 2026" Google Sheet, applied to the 2027 PGA Tour schedule (announced Aug 26 2026). The 2026 season was over before launch, so the site ships on season 2027.
- Zurich Classic (two-man team event) is deliberately a normal single pick at 2× — GP's call, Sep 2026.
- Autocomplete (`list_golfers()`) = seed table ∪ golfers from locked tournaments. `submit_pick` must NOT write to `golfers` — that leaked pre-lock picks.
- **Cards** (Sep 2026): the commissioner deals TCG-style cards (`cards` table) to owners; only the owner sees their hand (`my_cards`), plays one per tournament before lock (`play_card`/`unplay_card`), and plays reveal at lock (`tournament_cards`). **All points flow through `scored_points(tournament_id)`** — winnings × multiplier, then cards applied in `played_at` order: `multiply {x}`, `flat {amount}`, `duel` (higher raw winnings → ×2 base, loser 0; tie no-op), `steal {pct}`, `swap`, `shield` (nullifies duel/steal/swap/curse aimed at the holder), `mulligan` (lets `submit_pick` reuse a golfer that week), `custom` (text only — the commissioner rules on it via the per-pick **adjustment**: `picks.adjust` + `adjust_note`, set from Enter Results through `admin_set_winnings(..., p_adjust, p_adjust_note)`, applied by `scored_points` after every card and noted as "Commissioner: +$X (why)"), `fellowship {amount}` (partner card — both owners must play it on each other; +amount each, both $0 if either has $0 winnings = missed cut; resolved once per pair via `paired[]`), `curse {golfer, pct}` (In the Stocks: victim's points × (1+pct/100); if `golfer` set, `submit_pick` rejects any other pick for the victim — and skips the no-mulligan rule for the forced golfer — and scoring zeroes them if they didn't comply; the victim alone is warned via `my_constraints()` on the pick form, without learning who played it). `tournament_board`/`standings`/`season_picks`/`my_picks` all read from it and carry a `note` explaining the math. Adding an effect = add it to the `check` constraint, the `case` in `scored_points`, and `EFFECTS` in index.html (label/param/target/summary). Card art is stored as a data URL resized in the browser (`dcImage` handler; 640px for artwork, 760px for full cards) — no storage bucket. `full_card` (on `cards` and `card_library`): the league's real cards are finished images (title/type/text baked in, portrait ~2:3) — render them as-is (`.tcg.full`), auto-detected on upload when height/width > 1.25. The built-in frame for text-only cards deliberately mimics those printed cards: near-black body, double gold border with corner scroll SVGs (`--curl`), parchment panels with feTurbulence grain (`--noise`), EB Garamond; all frame sizes are in `cqw` (`container-type:inline-size`) with grid rows 7/46/6/31 measured off the paintings, so cards scale like prints and `fitCards()` only shrinks text that overflows. `EFFECTS[x].params` is an array of `{k,l,t}` inputs rendered by `dcRenderParams`; `EFFECTS[x].target` is the label for the owner it's played on (Opponent/Victim/Partner) or absent.
- **Card library** (`card_library`, George: "build up a huge pool"): the season-independent pool of designs. Dealt `cards` rows carry `library_id`; `admin_deal_from_library` copies the design into a new card. Commissioner UI: "Card library" grid (deal to owner / edit / retire-restore, with dealt counts) above the "Design a card" form; dealing a new design saves it to the library by default (`dcSaveLib` checkbox), `dcLibId` marks edit mode. Retire hides from the pool but never deletes. `admin_save_library_card` with null image keeps existing art.

## Security model — keep it this way
- The browser holds only the anon key. **All tables have RLS on and zero grants to anon/authenticated.** Nothing is readable or writable directly.
- Every read/write goes through `security definer` functions; only those are granted to `anon`. Owner functions take `(p_owner, p_pin)` and call `_owner_id()`; commissioner functions take `p_admin_pin` and call `_check_admin()`. PINs are hashed with pgcrypto `crypt()`.
- When adding a function: `security definer set search_path = public, extensions` (Supabase installs pgcrypto in `extensions`; plain `public` breaks `crypt()` — bit us on launch day), add it to the `grant execute ... to anon, authenticated` list at the end of the schema, and never expose an unlocked golfer name from it.
- Frontend calls functions with `sb.rpc(name, {p_...})` via the `rpc()` helper in index.html; errors thrown there surface as user-facing messages.

## Frontend structure (index.html)
**Every push must bump `const BUILD`** (format `YYYY-MM-DD-N`, top of the script). GitHub Pages caches index.html for 10 min; on load the page fetches the live copy with `cache: 'no-store'` and hops to `?v=<newBUILD>` if it differs — this is what stops owners running stale code (GP hit this on Sep 16 2026 and thought the library edit was broken).

Theme (Sep 2026, GP's brief): purple + green fantasy, white stag mascot. Palette tokens in `:root` (plum `--bg-*`, `--violet`, `--leaf` green, `--gold`), Cinzel display + Cormorant Garamond body via Google Fonts, firefly/mist background on `body::before/::after`. The stag is an inline SVG `<symbol id="stag">` reused via `<use href="#stag">` (header crest + Stag Club hero). No tagline under the title — GP: "the league rules cover this". Standings leader gets a white `.tag.stag` "Leads the herd". GP rejected an earlier outer-space theme; don't bring it back.

Views toggled by `show(view)`: `board` (This Week: pick form + who's-in; after lock also "Cards in play"), `standings`, `mine` (My Picks + change PIN), `cards` (My Cards: PIN-gated hand rendered with `tcgHTML()`, play/take back), `season` (grid), `stag` (The White Stag Club: hall of past champions from `champions` table via `list_champions()`; newest card glows), `admin` (Commissioner: enter winnings, owners, schedule, crown/remove champion via `admin_set_champion`/`admin_delete_champion`, settings). Shared data (tournaments, owners, `season` via `current_season()`) loaded once in `loadShared()`; an empty schedule shows a pointer to Commissioner → Schedule instead of a blank board. Owner name/PIN are kept in `sessionStorage` for convenience only.

## Discord
`settings.discord_webhook` (set via `admin_set_discord`, never exposed). `announce_locked()` runs from pg_cron job `announce-locks` every 5 min: any tournament with `lock_at <= now()` in the last 2 days and `announced_at is null` → `_discord_post(id)`, then stamps `announced_at`. `_discord_post` calls the **`announce` edge function** (`supabase/functions/announce/index.ts`, deployed via Management API `POST /v1/projects/{ref}/functions/deploy?slug=announce`, `verify_jwt:false`; auth = `x-announce-key` header matching the `ANNOUNCE_KEY` function secret and `settings.announce_key`; URL in `settings.announce_url`). The function reads with the service role (needs `grant all on all tables ... to service_role` — tables made through the SQL API don't get it), calls `_discord_message` + `_discord_cards`, and posts multipart to the webhook: picks as text, each card in play as an embed with its art attached (`attachment://cardN.jpg`), text-only embeds for cards without art. If `announce_key`/`announce_url` are missing it falls back to a text-only `net.http_post` to the webhook. The announcer key is at `~/.secrets/golf_announce_key` on GP's PC. `_discord_message` = picks + cards in play when locked; "who's in so far" when not. `admin_announce` posts on demand (Enter Results → "Announce on Discord") and returns the text. The DO blocks that create pg_net/pg_cron and (re)schedule the job swallow errors so the schema still loads on a project without them; `admin_discord_status.scheduled` tells the UI.
